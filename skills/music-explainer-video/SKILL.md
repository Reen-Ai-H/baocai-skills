# 无旁白音乐科普视频：方法总结

适用范围：用代码（Remotion + Python）制作**没有旁白**的音乐知识科普视频，主题可以是节奏、和弦、音阶、调式、音色、曲式、编曲等。画面、音乐和字幕负责讲清楚知识点，引用的歌由代码自己演奏，不用原曲录音。

来源：《和弦 · Chord》的制作经验（参考片《节奏》，开头 v5 版通过用户审核）。完整原文可参考项目里的 `docs/音乐科普视频方法总结.md`。

## 0. 一句话原则

**每讲一个新知识点，音乐必须真的发生一次变化；讲完马上用一首观众熟悉的歌证明它。**
讲解要循序渐进，不写"反思/设问"段落，也不靠堆概念制造悬念。

## 1. 工作流程（按顺序）

1. **拆参考片，画面和音乐都要拆。**
   - 量每段时长、切点、讲解页与歌曲段的响度差（实测：讲解页约 −19 dB，歌曲段约 −14 dB）、每段的曲风，以及进场前是否先收空再重击。
   - 逐秒拆开头 45 秒，看它怎么抓人：冷开场、最小单位、标题落在第一次组合上、15–20 秒一次极端演示、音乐奖励。
   - 结论写进文档（`docs/xxx_开头钩子分析.md`、`docs/xxx_原曲处理分析.md`），再开始作曲。
2. **列知识点，从易到难排序。**
   - 每个知识点配 1–3 首歌，先列一份候选歌单给用户挑。
   - 歌单要覆盖华语、欧美、古典、电子，多选 2015 年后的新歌。
   - 按章节注明每首歌用到的和弦或节奏型，以及出处。
3. **要谱子。**
   - 自动途径基本都走不通：和弦站没有旋律，简谱站有验证码，MIDI 站下载失败。
   - 由 Grok Bot 用浏览器主动去 EveryonePiano 这类站点截简谱，存进 `ref/sheets/`（文件名：编号_歌名_页码.png），再告诉制作方；不必先问用户，事后同步即可。没有可靠谱子的歌不进片，也不凭记忆写旋律。
4. **写计划，并请无上下文的审核者打分。**
   - 计划自成一体，包括结构表、每段时长、选歌、过渡方式和风险。
   - 另开一个没有上下文的 agent，按结构、钩子、过渡、顺序、穿插、新手清晰度、乐理准确性、可行性逐项打分。
   - 把审核意见和对应修改写回计划。只做一轮审核加一轮修改，不无限循环。
5. **先做 1 分钟预览，让用户审。** 开头决定观众留不留下，开头通过了再做全片。
6. **每轮反馈都存档。** 用户原话和截图存为 `docs/用户反馈_日期_主题.md`，逐条改完再交付。
7. **交付前跑 QC。** 检查项见第 7 节。

## 2. 结构公式

```
冷开场(4s) → 标题(2s, 短促一击) → 认识最常见的东西(≈10s) → 第一首歌奖励(≈8s)
→ 知识点 A(≤25s) → 歌 → 知识点 B(≤25s) → 歌 → … → 回顾快切 → 黑底标题
```

- **冷开场**：黑屏中一个发光的点，只响最小单位（一个音或一拍）。第二下出声时，纸面从这个点像墨滴一样晕开，同时出第一句字幕。
- **标题短**：只给 2 秒，一记短和弦重击加轻鼓，标题快进快出。用户明确批评过标题段"音效和长度太长，拖沓"。
- **先认识，再讲原理**：开头先让观众认识最常见的几样东西，比如 C G Am F 四个和弦，配卡片和组成音；马上用一首正好只用这几样的歌作奖励；然后才讲"它是怎么构成的"。
- **讲解与歌交替**：讲解每次不超过 25 秒就进一首歌。歌可以只有几秒，但必须是**一句完整的旋律**。
- **章内排歌**：最熟的在前，然后最新的，最后最意外的。相邻两章的风格在抒情和律动之间交替，同一首歌全片最多出现 2 次，第二次换一个段落。
- **数据彩蛋**：在合适的位置放 1 个有趣的数据，并注明出处和年份。例如王道进行"日本史上销量前 20 的单曲里约 40%"（出处：Wikipedia，2023）。
- **不要做**：吉祥物或角色小人（三个圆叠起来的"和弦小人"被评价为太丑）、"反思/设问"段落（如"音越多越好听吗？"），以及塞满知识点却不给歌的长段讲解。
- 专业名词出现时顺带用白话解释，观众（和用户）不一定懂乐理。

## 3. 引用歌曲怎么处理（关键）

学《节奏》：**不照搬原曲编曲**，只取旋律里最有辨识度的动机（hook），配一套为知识点服务的简化编曲。

- **旋律**：从简谱逐小节录入，取 1–2 小节，或者一句完整乐句。简谱是首调记法，可以直接移调。录入后对照歌词核对小节号。
- **编曲**（突出和弦的写法）：
  - 每次换和弦：一下和弦重音、一个根音低音、一层铺底 pad、一下底鼓。
  - 再加一种安静的标志性音色，提示原曲风格，例如 Faded 的拨弦合成器、Golden 的流行鼓组。
  - 正在讲的东西单独放大：讲七和弦，就让第七音单独亮、单独响。
- **响度**：旋律比伴奏高 2–4 dB。讲解页约 −19 dB，歌曲段约 −14.5 dB，母带整体 −14 LUFS。
- **进出**：进歌前收空半拍到一拍，强拍上用碎玻璃（shatter）转场切入；歌后回到讲解页时加一次白闪。歌曲段左上角放歌名、年份和风格标签。
- **底部轨道面板**（与《节奏》一致，不要用单行简谱）：
  1. 旋律层：横向钢琴卷帘色块，每块里写简谱数字。
  2. 和弦层：色块按级数着色（1 琥珀、4 橙、5 黄、6 蓝……），写级数加和弦名。
  3. 节奏层：底鼓画圆点、军鼓画方块、踩镲画短竖线，和上面的节拍网格对齐。
  4. 三层共用一根播放线。每段单独设定音高范围，避免旋律溢出到和弦层。

## 4. 画面系统

- **纸面讲解页**：暖灰纸色、墨色文字、朱红强调色；关键词标【】，加红色波浪下划线。右上角放当前主角（大号和弦名）。
- **只用几何图形**：点、条、色块、键盘、点列。音高间距按半音比例画，4+3 和 3+4 的差别能直接看出来。
- **讲解页必须一直在动**，每 2–4 秒至少一个视觉变化。通用做法：
  - 背景有彩色光斑缓缓上浮；整页在一段内推近约 5%，并轻微横向漂移。
  - 卡片轻轻漂浮，跟拍脉动；当前项外圈有扩散的光环。
  - 每个音走到播放线时，迸出该音颜色的火花和方形碎屑，同时扩一圈环；播放线所在的竖条随节拍闪。
  - 键盘跳音时，彗星拖尾沿弧线飞过去；取到的键发出暖色光并炸开火花，跳过的键飘出一个 ×。多个音同时响时向上射出光柱。
  - 标题出现时：冲击波、放射线、彩色碎纸。
  - 冷开场：每个音发出光晕、扩散环和火花。
- **歌曲场景页**：每首歌一张全屏风格化插画（不用专辑封面）。可以用场景讲情绪，例如同一条街，小三和弦时下雨，大三和弦时放晴。

## 5. 技术管线

- **单一时间来源**：Python 作曲脚本生成 `timeline.json`，包含段落、音符、和弦、鼓点、提示点和字幕。Remotion 画面只读这份 JSON，不自己定时间，所以改音乐后画面自动对齐。
- **Score / Sec 抽象**：每段设定速度、拍号、调、目标响度、章节号和字幕；用 `s.b(bar, beat)` 取时间点；`cue` 给画面打提示点；和弦用 voicing 加声部进行。
- **音源**：用自写的 numpy SF2 采样器加载 GeneralUser GS 音色库（可商用）。不编译下载来的 C 代码，也不伪装 UA 抓取网站。
- **简谱解析器**：支持 `1=C 4/4` 头、数字、`'`/`,` 八度、`_` 时值减半、`.` 附点、`-` 延长、`~` 连音和 `|` 小节检查。旋律以简谱字符串写在代码里，同时导出 `jp` 标签供画面显示。
- **混音**：每段先按目标 LUFS 调整，再叠音效（标题光点、标签"啵"声、跳音"嗒"声、进歌"嗖"声、环境声），最后整体压到 −14 LUFS。
- **音效**用代码合成，或用可商用的素材。付费生成服务只在用户明确要求时使用。

## 6. 过渡（"爽"的来源）

- 切换落在强拍上。进歌前收空半拍到一拍，再一记重击，新音乐正好在第一拍进来。
- 碎玻璃转场；推镜进入场景里的物件（窗口、唱片、路牌）；宫格放大，即某一格放大到全屏后开始演奏。
- 同调同速的歌之间只换音色和鼓，听起来像同一首歌换了人唱。
- 不同调、不同速的歌之间，用鼓加花或上行音效接，下一首在强拍横扫进来。

## 7. QC 清单（每次交付前）

| 项 | 目标 |
| --- | --- |
| 整体响度 | −14 LUFS，峰值 ≤ −1 dBFS |
| LRA | 6–9 LU（讲解页和歌曲段要有起伏） |
| 手机外放模拟（300 Hz–8 kHz） | 与整体响度相差不超过 3 dB |
| 近静止帧（YDIF < 0.15） | 整片 < 5%，并逐段检查，任何一段都不应超过约 20% |
| 截图联系表 | 每 3 秒一帧，检查字幕遮挡、旋律溢出、文字和标题相撞 |
| 歌曲旋律 | 对照简谱和歌词核对小节；旋律比伴奏高 2–4 dB |

交付说明写清楚这一版改了什么（逐条对应用户原话）和实测数字。只看画面、没有试听的，要明说"音色和平衡需要试听确认"。

## 8. 和用户协作的经验

- 选歌由用户定。先给候选表，含歌名、年份、片段、和弦和用途，用户勾选后再做。
- 用户反馈常常一句话里有好几件事，逐条拆开，逐条回复"改了什么"。
- 交付物是短预览加文档。先预览开头，通过后再做全片。
- 缺素材（谱子）时列清单，由 Grok Bot 自己去找；同时用占位把结构先做起来，素材到了直接替换。
- 有进展就及时同步用户：盯着制作会话的完成或报错信号（可设定时巡查），完成、卡住、断线都马上汇报或自行续上，不要等用户来催。
