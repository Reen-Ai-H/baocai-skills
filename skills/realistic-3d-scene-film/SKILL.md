# 写实 3D 场景（Blender 程序化 + Cycles）

给"用代码驱动 Blender 的编程 agent"用的制作手册。不绑定某台电脑、某个 agent、某个地点。第一个案例是《西湖·晨》（湖景，效果被认可），第二个是《上海·晨》（城市，**细节严重不足**，复盘见 `references/examples/shanghai-postmortem.md`）。这两次的教训都写进了下面的规则。

**一句话：氛围靠光和雾，真实靠细节，细节靠几何、材质和密度，而且必须放大到 1:1 去检查。**

> 雾和逆光是氛围，不是遮羞布。西湖能"藏进雾里"是因为湖景本来就以留白为美；城市、建筑、近景换成同一招，只会得到一排在橙色雾里的纸盒子。

## 1. 环境（每台机器第一次，结果写进项目 README）

- **Blender**：按顺序找：环境变量 `BLENDER` → `PATH` 里的 `blender` → 常见安装位置（Windows `C:/Program Files/Blender Foundation/Blender */blender.exe`、macOS `/Applications/Blender.app/Contents/MacOS/Blender`、Linux `/usr/bin/blender`、Steam 目录）。找不到就问用户，别猜。之后所有脚本都用 `$BLENDER`。
- 跑 `"$BLENDER" -b --factory-startup -P scripts/blender/probe.py`：打印版本、可用 GPU（OPTIX / CUDA / HIP / METAL / ONEAPI）、天空 / Principled / 体积节点的输入名。Blender 换版本输入名会变，`setin()` 这类按名字设值的函数名字对不上会静默跳过。
- 其他：Python 3 + `numpy` + `Pillow`（检查工具）、`ffmpeg`（视频）。做 three.js 再要 Node 和 Chrome（路径用 `CHROME_PATH`）。
- **素材下载**（可选但强烈推荐）：能联网就用 Poly Haven（CC0：HDRI、PBR 贴图、模型）。`scripts/tools/fetch_polyhaven.py` 下载到项目的 `assets/`。不能联网就全程序化，但细节要求不降。

## 2. 流程：每一步都有一个"过关条件"

| 步 | 做什么 | 过关条件（不满足不往下走） |
|---|---|---|
| 1 定一刻 | 地点 + 时间 + 天气 + 太阳高度方位，写成一句 | 用户认可 |
| 2 参考 | 找 3–5 张同题材**实拍**（用户给的或自己描述），列出"这类照片里一定有的细节"清单（见 `detail.md` 的题材清单） | 清单写进项目 README |
| 3 灰模 + 机位 | 只搭大形和相机，渲 clay（`detail_kit.py -- clay`） | 构图成立 |
| 4 细节层 | 按第 3 节"细节预算"给每个进画面的东西加二级、三级细节；补密度（前景、街道、植被、屋顶杂物） | **clay 图本身就像照片的素模**，不像积木 |
| 5 材质 | PBR：色差、粗糙度变化、脏污、边缘磨损、玻璃反射 | 无雾渲染下近、中景能认出材料 |
| 6 光和雾 | 低太阳 + 体积雾 + 逆光（默认），按镜调雾量 | 第 4 节雾量预算 |
| 7 英雄图 | 1 张全分辨率成片 | **过第 6 节细节体检** + 用户点头 |
| 8 分镜 / 九宫格 | 每镜一帧 | 每格单独过体检 |
| 9 视频 / 社媒 | 第 7、8 节 | 第 9 节交付清单 |

不要跳过 3–5 直接调光和雾：在灰盒上调氛围，调得越久越难回头（上海那次 200 多步全花在光、雾、水上，楼一直是盒子）。

## 3. 细节预算（核心）

**先算每个东西在画面里有多大，再决定要做到哪一级。** 物体在屏幕上的像素高度：

```
px ≈ 焦距mm × 物高m / (距离m × 36mm) × 画面宽px          # 36mm 全画幅横向
例：50mm、160m 高的楼、2500m 外、1920 宽 → 50×160/(2500×36)×1920 ≈ 171 px
例：200mm、同一栋楼顶 60m 段、2600m 外 → 200×60/(2600×36)×1920 ≈ 246 px
```

| 屏幕尺寸 | 必须有的细节级别 | 城市例子 | 自然例子 |
|---|---|---|---|
| < 40 px | 一级：剪影正确、比例对 | 远处楼群轮廓、有高低错落 | 远山层次 |
| 40–150 px | 二级：分段结构、明暗分面 | 楼层带、退台、屋顶设备、塔冠 | 树冠团块、岩体分层 |
| 150–500 px | 三级：重复构件和材质 | 竖梃 / 窗格（真几何）、阳台、檐口、空调外机、每块玻璃反光不同 | 枝杈、单叶、苔藓、岩缝 |
| > 500 px | 四级：微观和磨损 | 窗框倒角、污渍流痕、铆钉、灯具、栏杆 | 叶脉、树皮纹理、水珠 |

规则：
- **长焦放大一切。** 135–200 mm 对着一栋楼，楼就是 300–900 px，必须做到三、四级。做不到就别用长焦拍它，换成远景或用前景遮挡。
- **密度 = 真实感。** 真城市一眼几百栋楼、几千个屋顶杂物；真森林几万棵树。用实例（`detail_kit.instance` / 几何节点）做到这个量级，不要手摆 50 个。
- **所有硬边加倒角**（`bevel_all()`），零宽棱是 CG 感头号来源；逆光时倒角会接出一条亮边。
- **不同楼、不同树要不一样**：随机高度、分格、颜色、退台、屋顶，所有随机带 seed。
- **前中后三层都要有可读细节**，每张图至少一个"走近能看清材料"的东西。
- 地标要做到它在本片里最大那一镜所需的级别（上海中心在 200 mm 镜里是 900 px，那就必须有幕墙分格和扭转的楼层线）。
- 有真实数据就用：城市楼块用 OpenStreetMap（Blender 插件 blosm，或 overpass 拉轮廓 + 高度），地形用 DEM。比手摆可信得多。

具体做法（立面、屋顶、街道、植被、水岸、材质、PBR 贴图）见 `references/detail.md`；现成函数在 `scripts/blender/detail_kit.py`。

## 4. 光和雾：氛围的来源，但要守雾量预算

- 天空（Nishita / 多重散射）+ 太阳灯，**先验证方向**：天空 `sun_rotation` 和灯的朝向都要和"太阳在镜头哪边"一致，渲一张查顺逆光。
- 雾 = 大立方体体积：高度衰减薄雾 + 贴地 / 贴水噪声雾，各向异性 0.6–0.8（逆光才亮）。
- **雾量预算**：中景主体的局部对比不能低于 ~5%（`qa_detail.py` 的 `veiled` ≤ 0.30）。长焦看远处要按镜降雾（每镜一个雾乘子），否则整帧被前向散射糊白。
- 逆光剪影要有**边缘细节可剪**：剪影里的轮廓（女儿墙、天线、塔冠、树梢）才是逆光的看点，一块平顶盒子逆光还是一块平顶盒子。
- 太阳圆盘在浓雾里会糊，必要时在世界着色器里自绘（太阳方向点积 → 柔边圆盘 + 光晕）。
- 色彩：AgX（Medium High Contrast），16-bit PNG，再走 `grade.py`（bloom、S 曲线、冷暖、暗角、颗粒）。**颗粒加在最后，且检查细节时用未加颗粒的版本**。
- **定机位前先算光向**（上海第二轮：brief 要"玻璃幕墙反着朝阳"，机位却在逆光一侧，物理上不可能）：
  - 一块平面要把太阳反进镜头，它的法线必须大致平分"指向太阳"和"指向相机"两个方向。逆光拍时，朝向相机的那面在阴影里，只能得到剪影 + 边缘亮线。
  - 想要"受光面 + 质感"：侧光（太阳和镜头方向夹角 60–120°）。想要"剪影 + 光晕"：逆光。两者不可兼得，写 brief 时先选一个。
  - 逆光的水面，太阳到镜头之间必须是整片水最亮、碎成金色闪光的一条。没有就是太阳灯在光泽反射里不可见、水太粗糙或法线尺度不对。
- **天空色带**：先确认母版是 16-bit，量一行像素的平台长度（> 8 px 的平台就是台阶）。母版没台阶、8-bit 成片有，就在转 8-bit 时加约 ±1 级的抖动或颗粒，不要靠很重的颗粒盖住；天空最好有云或 HDRI 的真实纹理，不要一整块数学渐变。
- **蓝调 / 夜景是程序化城市的强项**：亮着的窗就是细节，见 `references/detail.md` §4。题材不限定时，城市优先考虑日落后 20–35 分钟。

## 5. 分镜（纪录片式）

- 焦段拉开：大全景 ↔ 中景 ↔ 长焦 ↔ 微距交替；每镜一个"在发生的事"（鸟起飞、船划过、鱼咬水面、灯熄灭）。
- 前景遮挡（树枝、栏杆、桥架）制造层次，但前景本身要经得起看。
- **每镜先过细节预算再定焦段**：想拍的东西撑不起那么大的屏幕尺寸，要么补细节，要么换焦段。
- 九宫格每格单独成立，能直接当图发。案例分镜表见 `references/examples/westlake.md`。

## 6. 细节体检（每张图交付前，必做）

自动化工具会帮你看，但**你必须看 1:1 裁切**。缩略图、九宫格（每格 640×360）看不出细节问题，上海那次 agent 看了 6 次九宫格就宣布"九镜都立住了"。

```bash
# 1) 实体蒙版（同一机位只渲一次，很快）
"$BLENDER" -b scene.blend -P detail_kit.py -- mask  qa/mask_S1.png 50
# 2) 量细节，产出热力图 + 三块 1:1 裁切
python qa_detail.py renders/S1.png --mask qa/mask_S1.png --out qa/
#    → S1  flat=0.12  veiled=0.08  detail_med=7.4  solid=0.46  verdict=OK
# 3) 灰模（去雾、去材质）：判断问题出在几何还是在光雾
"$BLENDER" -b scene.blend -P detail_kit.py -- clay  qa/clay_S1.png 32 50
```

- `verdict` 不是 `OK`（`GREYBOX` / `THIN` / `FOG-WASHED`）就不交付，回到第 3、4 节修。
- 打开 `*_crop1_flattest.png`、`*_crop2_center.png`、`*_crop3_richest.png` 逐张看，回答：**这块放大到手机全屏，像照片还是像建模软件截图？**
- 不给 `--mask` 时天空 / 水面会被当成"平"，留白多的构图会误报，所以正式检查一定带蒙版。
- 体检阈值是经验值：实拍城市 / 风景的 `detail_med` 通常在 4–12（边缘像素百分比），`flat` < 0.3。
- **蒙版的漏洞**：蒙版只量实体。主体只占画面一小块（`solid` < 0.2）时，`OK` 只说明那一小块有细节，剩下 80% 可能是一片平的天空。工具会打 `note=SPARSE`，这时必须回答"这片留白是有意的构图吗"，不是就改机位或焦段。（上海 03：`solid=0.11`、verdict OK，画面 89% 是平的褐色天空。）
- **数字过了不等于像**：地标认不认得出、光向对不对、倒影在不在，工具量不出来。逐条对 `detail.md` 的地标识别特征和第 4 节的光向检查。

## 7. 渲染预算

- 先算账再开渲：每帧秒数 × 帧数，给用户 2–3 个选项（分辨率、采样、降噪的组合）。
- 视频帧可以 75% 分辨率 + 32 spp + 降噪，再 Lanczos 放大到 1080p；**静帧不降**：128 spp 起，微距 / 拉焦 256，分辨率 100% 或更高。
- 竖图（3:4 等）改 `resolution_x/y` 并重摆相机，不要从横图裁。
- 长渲染逐帧、已存在跳过（可断点续渲）；有模拟（涟漪、粒子）的镜头必须从模拟起点顺序步进。
- 细节加上去渲染会变慢：几何用实例、贴图 2K 起步就够，`use_persistent_data=True`，体积步长按镜调。
- 自动关机这类动作只在用户明确授权后做（`night.sh` 要 `ALLOW_SHUTDOWN=1` 才会关机）。杀进程只杀本项目的。

## 8. 视频、声音、社媒

- three.js 只做视频提速，图像一律 Cycles（`references/threejs.md`）。
- 声音用真录音（`sound` skill，Freesound，CC BY 署名），环境床 + 按画面落点的点声，−18 LUFS。默认不用配乐。
- 剪辑：硬切、片头地点时间字幕、片尾片名，出母版（crf 15）和小体积（crf 23，手机 ≤ 30 MB）。
- 社媒（小红书等）：每张单发，首图放最强的；横图提醒可出 3:4 版；正文写清"不是实拍，是在 Blender 里用代码搭的"。

## 9. 默认审美（来自原用户，冲突时以用户这次的原话为准）

1. **所有图像用 Blender Cycles 出。**原话："效果上还是 Blender 更好，特别是静态图像，非常自然。"
2. **默认不放人物**（程序化人体有假人感），用动物和植物撑"生命"。
3. **动物长焦、逆光、小而远**；自发光强度 ≲ 1，不要排成"眼睛 / 脸"。
4. **细节要经得起放大看**：用户的话是"在细节上特别缺失"（2026-11-18，看上海九宫格时）。氛围和细节冲突时，宁可减雾也不要糊掉主体。
5. 纪录片剪法；九宫格每格独立成立。

## 10. 交付清单

- [ ] 每张图都过了第 6 节体检（带蒙版），并且自己看过三块 1:1 裁切；`verdict` 都是 OK。
- [ ] clay 图里主体有二级以上结构，不是积木。
- [ ] 太阳方向、倒影、阴影一致；物体没埋进地里也没浮空；没有"像脸"的发光排布。
- [ ] 地标逐条对过识别特征（剪影、遮挡、灯光签名），放大能认出是哪栋楼。
- [ ] 没有 `note=SPARSE`，或者有，但留白是有意的构图。
- [ ] 所有静帧来自 Cycles；画面里没有人（除非用户要）。
- [ ] 视频：帧数齐、时长准、响度 −18 LUFS 左右。
- [ ] **说实话**：列出最弱的 2–3 个镜头和原因（"03 塔身在 200mm 下仍缺幕墙分格"），**并且先修再交**；修不了的，写清楚为什么、需要用户做什么决定。不要把"还算不上好的地方"写进 README 然后照样交付。
