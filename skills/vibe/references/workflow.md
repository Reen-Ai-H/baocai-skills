# 工作流程（这位用户特有的部分）

通用的协作节奏（只问关键问题、先出可播放版本、交付清单、反馈日志）见 `explainer-video-craft/references/working-with-the-user.md`。这里只写这位用户特有的习惯。

## 0. 接到需求
- 逐字读完用户给的所有材料：参考片、资料文档、截图、BGM、`docs/` 里或 `msg*.txt` 里的要求。
- 用户说"不要用本地 skill"时，所有本地 skill 都不用（包括本 skill），直接选工具。
- 画幅先确认：发抖音就竖屏，否则问用户，或者看需求原文（MV、横屏科普常用 16:9）。
- 没有参考片时，联网找同主题、高播放量的优秀视频，学它的节奏和配乐编排。
- 用户给了自己写的文案或脚本时，主动提几个关键问题对齐分歧，用户欢迎被"拷打"。资料只是素材，可以大改。

## 1. 制作计划（正式开工前）
简短，一屏能看完：钩子（前 3 秒是什么、几秒进知识点）、分段（时长、知识点、例子、记忆点）、风格（配色、招牌手法、人物）、声音（每段配乐的情绪曲线、音效策略）。
需要用户选的内容：
- 风格、角色：出 3 张风格图或 3 个角色设定。
- 歌单、案例：整理成文档表格，写清理由和出处（例如这首歌真的用了这个和弦进行，要附谱子作证据），让用户勾选。用户删掉或替换的条目，严格照做。

## 2. 短样片
先出可播放的前 10 秒或前 1 分钟，不要只给静帧。用户常常按秒给意见（"2.6–5 秒不好，0–2.6 秒很好"），要逐条回应：好的原样保留，差的重做。

## 3. 反馈存档
每次用户的反馈都把原话存进 `docs/用户反馈_<日期>_<主题>.md`：

```
# 用户反馈（原话，YYYY-MM-DD HH:MM）
附图：…
> 原话…

## 理解
## 保留项（用户夸过的，不许改）
## 修改项
- [ ] …
```

改版前，先把所有"保留项"读一遍。用户给的精确数字（时间点、时长、数量）照做，不要自作主张地取整或调整。

## 4. 独立审片（可选）
用户要求时才做，按 `rubric.md` 里的模板，只审一轮、改一轮。用户说"直接发给我"就跳过。

## 5. 交付
按 craft 的交付清单来，另外：
- 附上审片评分，以及改了哪几条（如果做了审片）。
- 实测的近静止比例要和本 skill 的阈值对照。

## 6. 封面和标题
- 竖版 1080×1920 + 横版 1920×1080。用户指定了路径就用用户的；没指定就放进 `out/covers/`。
- 画面用片中最有代表性、最有钩子的一帧，重新渲染（不要截图），风格和正片统一。
- 文字少：一个大标题，最多再加一个挑战句或副标题；关键词标红。竖版的文字放在上半部分，避开底部 25% 和右侧按钮列。
- 标题备选给 5 个左右，每个说明它的角度：悬念、挑战、数字、反常识。
- 个人 IP「包菜的AI宇宙」作为小字，只在用户要求时加。

## 7. 沉淀
- 新的通用做法写回 explainer-video-craft（若已安装）。新的喜好或否决写进本 skill：原理进 SKILL.md 或 patterns.md。
- 不要把某一部片的具体内容写进 SKILL.md 正文。
