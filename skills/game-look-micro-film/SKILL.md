# 游戏感微电影

这是一本制作手册，来自《周五冰河时期》上集从初版到用户通过的全过程。人物名、台词、文件名都只是当时的例子，不是规定。

**一句话：画面是游戏的，节奏、调度和声音是电影的。** 用户原话：“这本质上是微电影，它不是游戏。只是说我们采用了这种游戏的风格。”技术上做到了不算做好了，每个元素都要问：它在推进戏，还是在演示功能？

## 0. 先分清：这不是知识视频

已有的知识视频 skill 可以借结构，它的硬规则不能搬过来。

| 知识视频的规则 | 微电影这边 |
|---|---|
| 无旁白、少文字 | 有对白和字幕。旁白用来解释和写主角心理 |
| 每讲一个知识点，画声变一次 | 每场推进一次戏：关系变了、局势变了、人知道了新东西。科普服从戏 |
| 近静止全片 < 10% | 不设硬线，逐段判断。落泪的长镜头可以不动，没人说话时的呆站不行 |
| 不要硬切，转场要顺 | 硬切、跳切、匹配剪辑是主要手法 |
| 卡音乐拍点 | 按表演、台词和动作切，音乐让路 |
| 不写自编金句 | 台词和旁白是剧作，要自己写，只是不能说教 |
| 用真实原图和出处 | 世界是虚构的，自己搭。可查的科普数字要真，虚构数字记入改动记录 |
| 人物可爱卡通，可以不要人物 | 人物是片子的核心，审美看第 3 节 |

两边通用的：开头留人，不空不拖不吵，用户夸过的不改，独立审片一轮，竖横封面和标题备选。

**冲突时：** 用户这次的原话 > 用户以前的原话 > 独立审片 > 本手册。用户的规则会更新，比如“先不配音”后来变成“全员配音”，“生图要加间隔”后来变成“多窗口并行”。存档时写日期，以最新的为准。

## 1. 开工前先定

1. **形式和质感用短样片定。** 做一段约 20 秒的可播放样片，要有走戏、近景和至少一句对白。用户说“就敲定这个画面质感了”之后，它就是全片标准。
2. **角色由用户挑。** 主角每种风格出全身、半身和进场合成图，并排对比。一旦选定就锁死，后面不换装、不换脸。
3. **基本规格：** 画幅、平台、集数、虚构地名。灾难题材要定好虚构说明放在哪，以及 AI 生成说明由谁加。
4. **改剧本的权限。** 小改可以自己做，逐条记入改动记录（改了什么、为什么）。主线、人物、结局要改，先停下来问。
5. **声音不要留到最后。** 这类片子默认要配音，所以镜头长度要给台词留余量（第 8 节）。

参考片只学手法。可以学 Until Then 的手机交互和“像素形 + 平滑光”的原理，不复刻它的人物、美术、场景或界面。片中也不出现真实品牌和公司名。

## 2. 导演规则

**开头。** 观众在这里决定走不走。
- 最强的钩子要最早出现，并且占满全屏。上集的 −32℃ 从第 4 秒、占画面左侧三分之一，改成了第 1.4 秒硬切全屏。
- 开场空镜不超过约 1.5 秒。
- 第一分钟里不要有长黑卡。
- 段子的快感一结束，马上给悬念，不要落进家常寒暄。

**慢不是切得慢，是画面里没事发生。** 初版平均镜头 2.75 秒并不算长，但约 41% 的秒数主画面不动，约 27% 的时长在读手机小字。所以提速要先看这三件事，不要只加切点：
- 主画面有没有事发生；
- 同一种“半身 + 虚化背景”占多少（初版 36%，审片建议 25% 以内）；
- 最长的 10 个镜头都值不值那么长。

**时间分给戏，不分给操作。** 初版高潮只有 8 秒，高潮前的电脑和手机戏却有约 16 秒。排完先看时间分配：最重要的时刻应该拿到足够的时间。

**情绪要升级。** 同一种“主角被否定”，同样力度连续来四次，中段就塌了。要么更狠，要么带来实际后果，否则就删。

**手法清单。** 每场至少用一个，别用成固定循环：
- 跳切推近：同一镜头按整数比例放大，保持像素方块。
- 匹配剪辑：上集用“贴满照片的墙”接“同角度只剩胶带印的墙”。
- 声音替画面说话：门声留在画外，镜头只拍留下的人。
- 反应镜头：大打击之后，切给接住它的人，停够时间，不要急着走。
- 低机位、过肩、慢推：打破“全景—近景—近景—全景”的循环。

**高潮的声音结构：全片最响，紧接全片最静。** 真静默只留呼吸。静默前的响要量出来，不要靠感觉（第 11 节）。

**插入镜头要像摄影机拍到的。** 物件贴在虚化背景上，一眼就是游戏演出。要重画成真实特写：东西放在桌上，有手，有环境。

**字幕只放台词。** 不放“（声音发抖）”这类舞台提示，情绪交给表情和配音。

**改之前先保护。** 用户或审片夸过的列成“保留项”，每次改版前读一遍。大改前留旧版目录，把旧场景当素材，用剪辑表重排（第 10 节）。

**连续性一次查清：** 人凑空出现或消失、道具凑空出现、不同楼层用了同一张图、门没有门扇、窗和舱的空间对不上、平地走路用了上楼姿势。第一次审片时，这些问题几乎全在。

## 3. 角色审美

用户的话：“记住我的审美。”

- **要：** 身形修长、干净、好看、有时尚感，轮廓利落，带一点打理过的造型细节（发带、帽子、眼镜、花衬衫）。
- **不要：** 胖、壮、邋遢、漫画式夸张、卡通定型。
- **路人和配角同样适用。** 选配角时，我曾按“更有烟火气、更贴身份”选，被用户全部改掉。先过审美，再贴身份。一个“老街大爷”也可以瘦、穿花衬衫。
- 用户授权自己选配角时也照此标准，一张图放 3 版对比，选定后记录原因。
- **表情库按剧本清点。** 上集第一批表情全是悲伤系，开心戏没得用，只能补做。开工前先列全片要哪些情绪，每种情绪都要配套的半张嘴、张嘴和眨眼。

## 4. 生活细节

用户最喜欢的是“合照 + 手写计划表”这种能停下来看的镜头。这就是全片的细节标准。

- 每个场景都放生活痕迹：合照、手写表格、招牌、菜单、比分牌、日历、门牌。文字用代码写进底图，保证清楚。
- **钱和数量要算得过去。** 账单的单价乘数量要对得上，总额要对得上，并按当地真实价格核对。查不到就写明是估价，不要说成查证过的。
- **日常对话就写日常。** 情侣聊天是留早饭、赶数据，不是“别忘了我们的环球旅行计划”。长期的共同目标靠墙上的东西交代，聊天里最多顺口带过。
- 细节要互相咬合：同一段视频、同一份账单在后面的场次回收，并且内容完全一致。

## 5. 道具说明弹卡

弹卡给**关键道具**，负责让工程空镜“有点东西”，让装备有爽感。它是一次演出，不是全片系统。

- **内容：** 名称、小图、几条人能看懂的属性、一句有味道的说明。文字高清，配弹出音效。
- **数量要少。** 上集从 8 张砍到 2 张，留的是用户点名的。不要连着弹，不要编号，不要长参数表。一连四张就成了背包界面。
- **感情戏里不弹卡。** 分手戏里弹过一张“两个睡袋，一个是给她的”，把最好的一句话藏在了最小的字里。后来删卡，改成主角亲口说出来。
- 解释性资料卡要先想一句人话能不能替代。例如“51 次模拟，3 次说这里会冻死人”，比两张资料卡管用，也能被旁白接住。

## 6. 手机戏

手机是情感和信息的主战场，全片用一个模块，内容和时间表分开写，画面和声音读同一张表。

**规则：**
- 人物先低头看手机，手机页再从左侧滑入，约占画面三分之一、全高，右侧场景压暗。
- 界面高清，不像素化（“形是像素，光不是”）。
- 页面要完整：头像、昵称、时间戳、历史气泡；银行、自媒体、论坛、天气都做成真的 App 页面。
- 对方发消息：先“对方正在输入…”，再出气泡，配提示音。
- 主角打字：输入框里按拼音 → 候选词 → 上屏汉字的顺序走，配按键声，点发送有发送音。
- 通知、扣款弹在**手机屏幕里**，不浮在场景上。

**和节奏的取舍：** 上面是“做得像”的标准，不等于每次都要演全。
- 完整的拼音打字，只给有戏的一两次（比如沉默三小时才回的一句）。其他的跳切到“已发出”和看回复，高潮前尤其不打字。
- 同一个答案不要揭晓两次：通知先报了余额，账户页的数字滚动就没悬念了。
- 手机内容要让观众知道是谁的手机、为什么能看到。
- 开场钩子可以破例全屏，等人物出现再回到手机页。

## 7. 对话戏的画面

这一节的两类 bug 都是用户先看出来的，我的抽帧没拦住。交付前专项查。

**朝向。** 先画站位图：谁在左、谁在右、看向哪。人在左边就朝右看，人在右边就朝左看，再对照每个近景。素材朝向不对就镜像，高清字幕最后一层画，不受影响。全身姿势也算：有人离开时，留下的人要朝着对方。上集曾经两人争吵时都背对对方，另一场日常对话也有同样的问题。修一处时，把全片对话都查一遍。

**表情。** 换嘴只能换嘴，眉眼要冻结。
- 只在脸部下方的嘴部区域里，替换和底图真正有差异的像素；眨眼同理，只动眼部。
- 嘴的来源要配套：开心的表情用开心的嘴。用悲伤底子的嘴去贴，就是一帧笑一帧皱眉。
- 给重要的戏排表情曲线，比如 震惊 → 担忧 → 强忍 → 落泪 → 死灰，每个近景对号入座。

**抽查方法。** 只看闭嘴帧是查不出来的。按语音音量找到**嘴张开的帧**抽查，主角和配角都查。女主的表情要单独过一遍全片，上集问题最重的就是她，因为她的情绪跨度最大。

## 8. 配音和旁白

- **声音分配：** 男主用用户在配音平台（ep1 用 BreezeBlue）保存的本人声音（《周五冰河时期》里是林默）。其他角色自己从声音库选，记录选了谁。密钥只在运行时从文件读，不打印、不写进代码和日志。
- **旁白：** 用男主的声音写内心独白和必要的解释，贴话筒、不加混响，字幕换一个淡色、不带人名。适度就好，也能补上删掉的资料卡。高潮的静默段不放。
- **情绪要整场连续。** 这是用户明确反馈过的毛病：“前面比较有情感，中间又变成旁白，后面又比较有情感。”原因和做法：
  - 连续的戏（争吵、爆发、发现、羞辱）**一口气录成一条**，写清这段情绪怎么走，再按真实停顿切开。不要逐句生成，每句都会从零开始起情绪。
  - 旁白也带当时的情绪。“压住情绪念”正是中间掉下去的原因。
  - 自动切点要吸附到真实的静音上，平台的时间戳不够准。切完检查句头句尾有没有被吃掉。
- **表演说明要具体：** 对谁说、什么姿态、哪个词加重。“生气地”不够用。
- **数字写成汉字**再送合成，字幕保留阿拉伯数字。
- **时长要预算。** 配完音，认可的剪辑从 3:52 涨到 4:36，定版 4:33。处理顺序：压句中长停顿 → 轻微提速 → 拉长镜头。情绪最重的长句不加速，提速也会伤情绪，别叠太多。用户认可的剪辑顺序不动。
- **说话的人嘴要动**，跟语音音量走（约 8 Hz）。规则看第 7 节。
- **混音要轻：**
  - 按空间给混响：楼梯间长、硬墙客厅短、办公室暖、室外开阔。
  - 按状态处理：画外放远放闷，喊到轻微破音，虚弱时少高频，喘着说话时垫呼吸。
  - 说话时环境和音乐让开。

**坦白说：** 我听不到声音。音色、表演好不好、情绪接没接上，只能量结构，最后要用户听。交付时说清楚，并请用户指出具体哪句，单句重录。

## 9. 声音轨

- **真实录音优先。** 拟音、道具、环境音用 Freesound 等真实录音。合成只留给音乐性的声音和极短的界面音。用户听过合成版后，要求全片声音整版重做。
- **环境床要足，每场先想这个地方本来有什么声音：** 球场有拍球、跑动、远处喊声；机房有轻微机器底噪；闹市有熙攘人声，低通到听不清内容。第一版音乐比环境响约 8 dB，环境完全被盖住，音乐要压下去。
- **一段戏不能只剩一种声音。** 用户原话：“整个声音只有女主的惊呼声，显得很不自然。”后来换成钥匙、门、箱子、冰箱和隔壁的胶带电钻声，只留一口吸气。
- **大揭示不要靠“音效很大”。** −32℃ 弹出时，不协和和弦加重低音被用户说不好听。改成所有声音切断，只剩手机一震、一个很轻的低音钢琴和极轻的冰声。
- **选片：** 看下载量、评分和描述，再用 ffmpeg 量起音点、尾巴和频段。热门不等于合适，开头可能有几百毫秒静音，会导致打点不响。
- **授权：** 非商用可以用 BY-NC，CC-BY 署名，全部留在 credits。
- **发布前必须处理：** 换掉未授权的微信提示音；确认 AI 配音和 AI 音效平台的使用条款。

## 10. 流程

```
原话存档 → 计划 → 短样片 → 分场制作，每场出预览 → 总装
→ 用户反馈存档（原话 / 理解 / 保留项 / 修改项）→ 改一轮
→ 无上下文盲审打分 → 按审片再改一轮 → 给用户看 → 用户点头才算过
```

- **原话一字不改进存档。** 反馈常常是语音转的，会有同音字和截断（“下级”是下集、“何以”是何姨；有一次开头被截掉了）。能判断的按原意做，把理解写出来，别脑补新需求。
- **精确反馈逐条回应：** 改了什么，没改什么，为什么。
- **盲审**用 `references/rubric.md`：不给制作过程，也不让它看用户反馈。审片意见和用户原话冲突时听用户的。只审一轮。
- **任何新预览立刻告诉协调方**，给路径、时长和改了什么。版本号写进文件名（r1、r2…），否则“这一版”会说不清。
- **一集没过，不开工下一集**，除非用户明确说开工。上集初版还没经过重剪，下集就照同一套做了，用户看完说下集“质量不行”，上集也要改。下一集要用的是**用户通过后**的方法。
- **生图：**
  - 能合并就合并：一张放 3 版角色，全身加半身放一起，两三个场景或九宫格放一张，道具做拼图再切。
  - 只有主角关键镜头和高精度大场景才单独生成。
  - 每批不超过 10 张，先把“这批多少张、每张有什么”写进计划，可以多窗口并行。一批 40 张被用户批评过，限流后单张会涨到几十分钟。
- **报告要诚实：** 哪些量过、哪些没量、哪些是判断。说“最响”“没问题”之前先量。

## 11. 工程和 QC

**管线。** 单一时间轴是硬规则：画面、字幕、手机、拟音、配音读同一份数据，改长度不失步。渲染器按需选 Remotion 或 Python。**注意：ep1 实际全程是 Python + ffmpeg，没有用 Remotion**，所以 Remotion 这条路在这类片子上还没验证。

**三个决定性的做法**（细节见 `references/pipeline-and-qc.md`）：
1. **形是像素，光不是。** 角色和场景落在固定像素网格上，光、雾、字幕和界面是全分辨率。这才不像“挂图片晃来晃去”。
2. **旧场景是素材，剪辑靠一张表。** 表把新时间映射到素材时间，字幕、手机、拟音自动跟随。重剪不用重写分场代码。
3. **声音一次混完。** 总装只拼视频轨，声音按全片时间轴一次混，统一响度。

**出片前跑 `scripts/qc.py`，再逐项查：**

| 项 | 怎么查 | 看什么 |
|---|---|---|
| 联系表 | 每 2 秒一帧 | 钩子、穿帮、同一构图重复、半身占比 |
| 响度 | 整片约 −14 LUFS，看 LRA | 真峰值要量编码后的文件，分享版也要量 |
| 高潮位置 | 脚本报短时最响和最静 | **最响是不是高潮？** 只量 RMS 会看错 |
| 近静止 | 量主画面，不含手机页 | 逐段问：是戏需要，还是我没做动作？ |
| 说话帧 | 按语音抽嘴张开的帧 | 表情有没有变，朝向对不对 |
| 站位图 | 每场对话画一张 | 视线对上了没有 |
| 保留项 | 逐条对 | 夸过的都还在 |
| 对外声明 | 账单、数字、授权 | 估价和虚构数字都已标明 |

**交付：** 成片路径和版本号、相对上一版的改动、实测数字、哪些没法验证、需要用户听的点、版权待处理、竖横封面、约 5 个标题（不写片里没有的事）。下一步只提一件。

大文件要另出分享版并分段拷贝，拷完核对大小或校验值。分享版只用于快速过片，压得很重，画面细节要看母版。

## 12. 最容易再踩的坑

1. **把功能做全当成做好。** 手机、弹卡、打字都很像真的，节奏却死了。
2. **修一个问题带出新 bug。** 给配音加嘴型，把全片女主的表情改坏了。每次加系统级功能，都回查已通过的东西。
3. **逐句配音。** 单句听都不错，连起来情绪就断。
4. **只抽闭嘴帧、只看中间帧。** bug 全在说话的时候。
5. **靠感觉说“最响”。** 上集通过版的高潮电弧就不是全片最响（见 `references/pipeline-and-qc.md`）。
6. **分享版没量。** 低码率 AAC 能把真峰值顶过 0 dB。
7. **上一集没过就开下一集。**
8. **选角贴身份不贴审美。**
9. **聊天和账单写得太“有用”。** 日常要像日常，账要算得过。
10. **发布前忘了换提示音和核对条款。**

## 14. 短喜剧与执行更新（2026-11-07）

### 授权与导演职责
- 用户给了精修剧本并明确让开工时，按这版存档后开工，不再重问是否开始。原话与执行稿分开，用户允许的微调写进改动记录。
- CC 要以专业导演身份负责表演、镜头调度、剪辑和节奏，而不是把带时间戳的台词逐项做成幻灯片。可以为作品效果调整停顿、动作长度、镜头顺序和同义台词；未经授权不换主线、核心包袱、人物和结局。
- 新短剧单独建工程，旧片角色、配音与已批准画面作为只读素材复用，不覆盖旧项目。人物脸与名字可沿用，但新片用户明确指定的体格、性格优先于历史默认。

### 一分钟短剧
- 第一帧就发生最吸引人的事。声音可先行：主角反应特写 + 画外动作声 + 道具后果，再揭示全景；不要先铺环境和片名。画外表现是叙事选择，不是“保证避审”的方法。
- 先算真实时长预算：对白、吸气/咽咖啡等表演、关键道具动作、停顿、转场分别占时。写着60秒不代表演得完；先用临时配音排时间轴，超时先删解释和重复反应，不一味加速配音。
- 开场钩子→极短前情闪回→回到同一动作继续→包袱升级→干净收尾。闪回只交代必要因果，不把整帖堆成读屏；重要评论一眼可懂，非关键打字跳过。
- 笑点靠认真表演荒唐事、礼貌与动作的反差、围观者的反应；不要加旁白解释笑点。冷面角色也要有细小视线、杯子停顿、身体后移，不能等于不表演。
- 用反应切、声音桥、动作匹配、硬切、跳切压时间；不机械重复近景—全景。续杯等长现实过程可跳切，保留前后人物姿态形成笑点。
- 道具连续性单列检查：眼镜摘下且放远，之后不能无故再次掉落；杯子余量、冰块、袖口、人物朝向与掌掴左右手全片一致。夸张音效仍要服从空间，咖啡厅不要无缘无故用山谷长回音。动作戏以自愿、非血腥呈现，严禁声称某个剪法必然过平台审核。

### 组合生图
- GPT 生图可补齐素材，但不按每个小元素单独生成。优先整场构图、同角色多姿态/表情拼图、可切分的道具组合与场景视角组；每批先写清清单，仍不超过10张。
- 同一幅图的角色位置、光线、透视和物件比例一起解决。拆图后核对边缘、朝向、尺度；只有组合无法满足的关键特写才单独补图。

### 大文件交付的已验证补充
- 在当前传输通道上，8 MiB（8,388,608字节）分卷、每批最多3个并行已成功交付。高并行出现暂时不可达，先核查已落盘文件再补传缺段；拆小提高可靠性，不保证提高网络速度。
- 分卷写入明确临时子目录，按数字顺序二进制合并；最后一段从源文件实测长度，不手算或把路径字符串长度当文件大小。最终SHA-256与源文件一致后才宣布完成并删除临时分卷。
- 上传云盘或临时站要先确认服务支持的大小、有效期与授权。只有上传完成且真实下载入口可用，才说有下载链接。展示页不是文件；下载后检查字节数/类型，不把HTTP成功的网页当成视频。
- 不擅自在用户电脑落地文件；用户指定“只在你的电脑上传”时只用自己的电脑。用户另行明确要求本地下载或直传后，才写入其指定目录。
- 保存交付基线：版本、时长、尺寸、源路径、字节数和哈希。机器恢复后的文件修改时间变化不代表新渲染，不能仅凭mtime挑“最新版”。
